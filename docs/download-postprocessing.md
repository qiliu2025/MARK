# 下载文件设置

MARK 右上角设置中的“下载文件”提供两个独立选项。

“保存方式”控制后续开始的观测和精密产品下载任务。默认保留原有的年／年积日（DOY）目录；精密产品沿用其产品类别子目录，ANTEX 沿用原有类别／中心目录。选择“统一放在保存目录”后，文件直接写入该任务的保存目录。设置不会迁移已经下载的文件，任务运行时不能修改。

勾选“下载后询问是否解压与 RINEX 转换”后，整个观测下载计划结束时会弹出一次确认。默认不勾选。精密产品不执行此步骤。

确认框列出本次待处理文件数量、各磁盘的建议额外空间和当前可用空间。空间估算包括展开后的文件、Compact RINEX 转换、临时工作文件及 256 MiB 安全余量；它是保守估算，不是精确大小。GZIP 使用原始大小记录，ZIP 使用中央目录；尺寸记录不足或可能超过格式上限时使用保守倍率。空间不足时，清理所列磁盘并点击“重试”；也可以取消，下载文件保留。处理中持续检查空间，遇到不足会安全暂停，再次提供重试或取消。

此步骤只处理本次任务成功下载及因本地已存在而跳过的文件，不扫描或清理整个保存目录。支持 GZIP、Unix compress（.Z）、ZIP、TAR/TAR.GZ、BZIP2 和 XZ；支持压缩包中的多层压缩文件。Compact RINEX `.YYd`、`.d`、`.crx` 通过官方 CRX2RNX 4.2.0 转换为 `.YYo`、`.o`、`.rnx`。每个输入文件使用独立临时目录，只有所有结果提交成功才删除该输入的压缩包或 Compact RINEX。失败或取消保留原件；已经完成的其他文件保留处理结果。存在内容不同的同名输出时拒绝覆盖。

工具随软件分发，无需单独安装或配置本机路径。工具版本、来源、许可证及 Hatanaka 参考文献见 `resources/download-tools/README.md`。

多个文件采用有限并行处理，依据 CPU 核心数同时处理至多 4 个输入文件。同一文件的解压、转换及校验按顺序完成，最终提交输出也会串行检查同名冲突。临时输入优先使用同磁盘硬链接，避免重复复制大型文件；磁盘不支持硬链接时自动采用复制。取消和空间不足会停止所有未完成的处理。

开发验证可以设置绝对路径环境变量 `GNSS_DOWNLOADER_UI_STATE_PATH` 使用独立 INI。正常使用仍保存到原有 `%LOCALAPPDATA%/GNSSDownloader/ui_state.ini`。
